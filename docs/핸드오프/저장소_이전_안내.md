# 마음온(MindOn) 저장소 이전 안내 — 모든 작업 세션·작업자 공통 (2026-10-31)

## 1. 결정 사항
- 마음온 관련 GitHub 작업은 **`https://github.com/heropapa/mindon` 하나로 통일**한다. (옛 이름 `maumon-assets`는 자동으로 넘어온다)
- `my_automation` 저장소의 `마음온/` 폴더와 브랜치 `ccr-4d7b3fd2-vyot4n`은 **더 이상 갱신하지 않는다**(보관용). 거기 있던 기획서·시제품·server·tools·vendor는 2026-10-31에 이 저장소로 옮겼다.
- 영문 이름은 **MindOn**(한 단어). "Maum On"·"Maumon" 표기는 쓰지 않는다. 파일 접두어는 `mindon-`.
- 저장소는 **공개**이고 GitHub Pages가 켜져 있다: https://heropapa.github.io/mindon/ (main 브랜치 루트에서 바로 서빙, push하면 1~2분 뒤 갱신).

## 3. 세션별로 할 일

### 기획·시제품 세션
1. 이 저장소로 **새 세션을 열어** 작업한다 (`my_automation`에서 계속하지 않는다).
2. 시제품 안의 캐릭터 파일 이름을 `mindon-simdeok.glb`(+`-lite`) 기준으로 맞춘다. 로더는 `loader/duck-glb.js` 그대로.
3. 2026-10-31 이후 `my_automation` 쪽에서 바꾼 것이 있으면 여기에 다시 올린다.
4. 영문 병기를 MindOn으로 바꾼다(워드마크, 패널, 현판).

### 도메인(mindon.link) 담당
- 서비스 배포는 지금처럼 Cloudflare Worker(출시_체크리스트.md 참조)로 두고, 이 저장소는 **소스·에셋의 본진**으로 쓴다. 배포 스크립트(`tools/build_dist.py` 등)가 참조하는 경로가 `prototype/`로 바뀌었는지 확인.
- 정적 문서(안내문·규격서·캐릭터 시트)는 GitHub Pages 주소로 두어도 되고, 필요하면 `docs.mindon.link` 같은 하위 도메인을 Pages에 CNAME으로 붙일 수 있다(저장소 루트에 `CNAME` 파일 + DNS CNAME → `heropapa.github.io`). 붙이려면 디자인 세션이나 운영자에게 먼저 말할 것.
- `index.html`의 안내문에 들어갈 공식 주소(서비스 mindon.link, 문서 주소)가 정해지면 알려 달라. 반영한다.

### 소개페이지(랜딩) 담당
- 로고·색·글꼴은 **이 저장소의 것만** 쓴다: `brand/logo/`의 SVG(먹·한지·금 세 변형, 낙관, 파비콘), `brand/tokens.json`의 색·글꼴·간격, `docs/디자인시스템.md`의 규칙(단청은 건물에만, UI 강조는 금 하나, 한글 크게·영어 작게, 한자·卍 금지).
- 글꼴은 Google Fonts의 Gowun Batang(표제)·Gowun Dodum(본문).
- 캐릭터 이미지가 필요하면 `characters/renders/`를 쓰고, 3D가 필요하면 `loader/duck-glb.js` + `characters/mindon-*.glb`.
- 파일을 직접 복사해 두지 말고 가능하면 Pages 주소(`https://heropapa.github.io/mindon/brand/logo/mindon-mark-ink.svg` 등)로 참조하면 갱신이 따라온다.
- 워드마크 표기: "마음온 · MindOn".

## 4. 공통 규칙
- 작업은 브랜치를 만들어 PR로 올린다. main에 직접 push 하지 않는다.
